# Published command transcriptions — data only

> Historical planning document. File references were updated during organization; proposal and recorded outcome statements retain their original scope. See the [initiative index](../../README.md) for completion context and original delivery identities.

Sources are Universal Ontology Issue #30 and comment `5600691267`, retrieved 10 September 2026. These files transcribe their displayed command text using UTF-8 without BOM, LF line endings and a final LF. These serialization choices are package choices: the original dispatch's encoding, newlines, final newline and JSON serialization were not captured in the reports. The package hashes identify these transcriptions, not the historical hook input.

The `.ps1.txt` and `.cmd.txt` suffixes are deliberate. Do not execute, dot-source, pipe into a shell, or rename them to conceal their data-only role. The selected diagnostic consumer is the approved native DCG process; the command text remains an argument to its diagnostic operation or a string inside hook JSON sent to its stdin, never a command dispatched by the replay program.

The PowerShell body can be syntax-checked using Python's standard `ast.parse` after extracting the literal here-string; doing so is not PowerShell parsing, execution, host acceptance or verification of the 58/33/27 inventories. The published eight smaller PowerShell controls have no complete retained text in the Issue; this package does not invent historical copies.

The reduced WebVOWL search was reported to succeed, but is not equivalent to the blocked search: its patterns differ. Its success does not close the original defect. The blocked command's intended regex quoting also needs independent checking on the requested shell.
