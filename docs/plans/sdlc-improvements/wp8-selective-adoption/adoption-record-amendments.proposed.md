## Amendment A — Interpret selective adoption in UO's existing adoption guide

**Target:** `docs/sdlc/adoption.md` in UO. **Operation:** add this explanatory section without changing historical source/host records. Reuse equivalent accepted wording if it exists by implementation time; do not duplicate it.

```markdown
## Selective SDLC adoption and product qualification

An adopted change is identified by its accepted source revision, the selected
components, the destination revision and any retained local adaptations. A shared
package version does not establish identical files, generated configuration or
host behavior. Preserve earlier import and adoption records as historical evidence.

Qualify the selected shared correction in Universal Ontology first. Each downstream
repository then requires its own accepted adaptation and qualification. Inspect the
complete writer, reader, schema, launcher, setup and test dependencies of the
selected correction; do not replace the entire SDLC directory or the adopter's
verification profiles. Preserve repository-specific runtime and product consumers.

A generated-configuration check is not proof of host loading or trust. Record the
actual host, covered command paths, native Security inventory/writer scope and
remaining limitations where those capabilities are relied upon. Existing evidence
may be reused only for its unchanged applicable source, host and contract.

Keep product outcomes separate from control adoption. The combined MCP/SHACL
result requires its actual accepted implementations, source context, final combined
object and semantic consumers. WebVOWL's native source-grounded artifact and ONI's
installed real-description consumer require their own scoped evidence. Neither a
source test nor a passing aggregate establishes an unobserved user outcome.

Stop propagating an implicated failed correction. Preserve active state, failed
runs, original scan bundles and retained content while an accountable owner chooses
a bounded compatible recovery. Do not reset dirty worktrees, relabel old receipts,
refresh digests or rewrite accepted history to complete adoption. Resource release
remains governed by the existing temporary-artefact procedure.
```

This section reiterates the parent WP8's boundaries at their existing documentation owner. It must not change package version, risk classes, native schemas, baseline acceptance or host permissions by implication.
