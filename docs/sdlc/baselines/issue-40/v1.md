## Problem, affected party and desired outcome

Implementation handoff removes the active pointer, while surviving resource
obligations remain scattered in historical records. The existing status command
only prints active state. Maintainers need to find retained resources, their
consumers, preservation evidence and next actor after implementation ends.

Implement the WP3 resource-disposition increment of the SDLC implementation plan
dated 2026-09-10, following WP0 preservation and WP2 checkout exclusivity.

## Accepted behaviour and prohibited effects

- AC-301: Add `record-resource-disposition --input <contained-json-file>`.
  Strictly validate bounded UTF-8 input against the caller-input branch of the
  accepted resource-disposition schema. Write and read back a complete, uniquely
  named snapshot under the coordinator's existing runtime handoff store without
  replacing history or modifying active tasks, verification receipts or resources.
- AC-302: Change `status` to a version-1 JSON envelope containing scope, observed
  time, original active state and its read status, recorded resource dispositions,
  current observations, attention items, unattributed native worktrees, legacy
  handoff count and explicit read problems. Support handed-off/idle checkouts.
  Reserve stdout for JSON through the direct Node and silent npm entry points.
- AC-303: Resolve history through explicit same-resource supersession. Preserve
  conflicting leaves; reject dangling, cyclic, self and cross-resource references.
  Never choose a winner by timestamps, UUID order or filesystem modification time.
- AC-304: Use native Git porcelain/NUL inventory with no optional locks and a
  15-second process timeout. Bound reads to 256 KiB per snapshot, 4096 handoff files
  and 16 MiB aggregate. Report incomplete reads, malformed state, movement and
  conflicts with usable partial output and nonzero status. Ordinary retention is
  a successful status read, not a failed implementation.
- AC-305: Separate recorded assessments from present observations. Show native
  nesting, changed candidate HEAD and fresh-inspection requirements. Do not read
  arbitrary referenced files, traverse another worktree's runtime, fetch evidence
  URLs, execute recorded commands or infer unchanged dirty content from HEAD.
- AC-306: Record removed-confirmed only with declared actual operation evidence
  and fresh permitted registration/path absence observations. Reject unresolved
  containing storage, nested registrations, coordinator/main disposal claims and
  incomplete readback. No production code removes resources or changes Git state.
- AC-307: Route helper-only changes to the existing SDLC checks. Exercise recording,
  idle status, real linked/nested worktrees, malformed/unreadable data, publication
  faults, Unicode JSON output and absence of resource mutation with native tests.
- AC-308: Apply the exact accepted policy amendments. Reconcile actual WP0 holdings
  into the stable coordinator record within existing ownership/storage authority.
  Preserve held outcomes and pending consumer/removal decisions without fabricating
  a live removal exercise or claiming all resources have been disposed of.
