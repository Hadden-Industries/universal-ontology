# Editing policy acceptance tasks

Use the exact generated candidate and record its input digest, source revision, browser, theme and viewport.
Do not coach participants towards an answer.
Record success without help, time, interpretation errors and observed severity for each task.
Recruit at least five contributor-oriented and five technical-reference-oriented participants, where practicable including people who did not implement the policy.

Contributor tasks:

1. Find the first action before creating a concept.
2. Determine whether a property requires a definition.
3. Find the identity, creator and creation information for an ordinary entity.
4. Explain the obligations when changing an existing entity.
5. Determine whether every Distribution needs a media type.
6. Explain Dataset versus Distribution.
7. Follow a contributor summary to its exact technical rule.
8. Identify a judgement that executable validation cannot establish.

Technical-reference tasks:

1. Open the direct `#ep-preflabel-label` anchor.
2. Distinguish local-name normalisation from exact label correspondence.
3. Identify all constraints for `EP-DISTRIBUTION-MEDIA`.
4. Find `EP-MODIFIED` source and provenance.
5. Explain unavailable comparison context and unevaluated obligations.
6. Identify the severity of a failing rule.
7. Explain which scope selectors overlap.
8. Find a preserved technical example without using contributor guidance.

For live Wiki smoke testing, check direct anchors, all seven diagrams, light/dark selection, PNG fallback, narrow rendering at 320 CSS pixels and keyboard operation of links and disclosures.
Verify operating-system and GitHub theme differences where practicable.
Include calibrated assistive-technology testing and document any platform limitation separately from authored-content defects.

Acceptance requires at least 90% uncoached task success, correct interpretation of optional presence and unevaluated state by every participant, working summary-to-rule navigation and no unresolved severity-1 or misleading-diagram finding.
This is an operational threshold, not a population-confidence claim.
Record observed results in [acceptance-results.md](acceptance-results.md).
